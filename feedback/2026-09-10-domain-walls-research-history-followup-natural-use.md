## 核心澄清

agent 的建议是把 AITP 用作“可恢复研究认识演变的记忆”，而非更密的进度流水账。
减少重复摘要不等于只保留最新结论，更不等于删除失败路线、反例或旧判断。
保留这些内容有助于回答“当时为什么这样想”，但本次没有证明 AITP 比保存同样
证据的 plain files 更好。此前过重的使用方式仍有 agent 自身的责任。

## 六项优化建议：讨论结论，尚未实施或验收

### 1. 记录认识变化，而不只记录完成动作

在现有正文中写清：物理问题、假设与选路理由、新结果或反例、改变了什么判断、
没有解决什么、下一步为什么必要。不要为此新增一套必填字段或语义状态机。

本项目的例子是：“候选 junction 理论中指定线算符扇区的换道数据已得到，
但物理墙重新连接的映射仍缺失”。不能将两种完成状态合并成“junction 已完成”。
一个计算可以继续成立而物理解释被收缩；应注明变化，不把 supersedes 当作
旧结果全部失效的科学判决。没有突破的负面结果也可以有价值，无须包装成进展。

### 2. 保留历史，但让文件分工明确

| 载体 | 主要职责 |
|---|---|
| 普通推导文件 | 完整公式、约定、证明、反例与文献 |
| Entry | 一个有后续意义的事件或认识变化，加证据定位与限制 |
| 当前 working Note | 综合后的认识、假设、障碍和下一步理由；只在综合确有变化时更新 |

不习惯性同时生成三份同义叙述；旧 Entry / Note 仍保留。
有信息量的失败应说明排除了什么、失败在哪一步、什么条件改变后值得重试。
不要以“轻量化”为由删掉失败证据，也不要求记录每个临时代数操作。
无新增事实的状态问答保持零写入；必要的会话维护和保存校验仍遵守当前规则。

### 3. 同时保障记录留存和原始证据留存

哈希标识版本，不保存文件内容。关键结论应对应可取回的推导版本或快照，
定位到章节、公式、文献版本；后续修订注明哪些结论保留、哪些解释修改。
普通草稿不必逐行归档。无法取回旧版本时报告具体缺口，不拿同名新文件冒充，
也不把版本缺失直接当作物理结论错误。这个建议不授权本轮迁移或备份整个项目。

### 4. 按物理疑问恢复，而不只按日期执行最新下一步

阅读顺序可以是：当前认识 → 为什么形成此认识、曾试过什么 → 原始支持或反例。
使用现有 Note、refs 与定向检索即可先实践，不要求新索引、向量库或 lineage CLI。

例如恢复当前任务时，需要问“SU(5) 是否已试过类似映射、当时缺了什么、本次
结果补上了哪一项”，而不是把最新 next_action 当成路线必要性的证明。
上述是恢复问题示例，不是本次已完成对全部 SU(5) 旧推导的重新审查。
当前摘要应短，但历史深读入口要保留；不得根据时间线事后编造选路理由。

### 5. 分开记录健康、论证质量与物理完成度

区分版本/引用可访问性、数学推导检查、物理识别的假设、研究目标完成度。
运行时校验主要处理第一类，不能自动裁决后三类；“记录完整”不是科研验收。

检查展示应让影响当前论证的 finding 容易找到，并保留完整报告供追查；
不能为了减噪而隐藏错误、改旧 pin 或跳过必要验证。历史维护工作不算物理突破。
优先落实已有报告复用和按需阅读指导，而不是再建立一套平行检查系统。

### 6. 按研究效果验收，不按记录数量验收

若另行获准评估，考察中断后能否找回假设、反例与障碍，是否减少重复推导，
是否避免把条件性结论说成定理，能否有据说明认识改变，以及人类纠错和模型成本。
比较 plain files 与轻量 AITP 时保留相同原始证据、失败样本及测量边界；
不能只比较工具数、记录数或一次回答速度。本次没有开展这种对照。
